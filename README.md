Contact Form Processor (local_contactform) turns any custom HTML form, embedded block, or FilterCodes template on your Moodle site into a secure, styled email submission system—without storing sensitive personal data in your Moodle database.   Whether you need a public Contact Us page, a technical Support Request desk, a student Course Request portal, an in-course Quick Question box, or a one-click Course Check-In button, local_contactform processes submissions reliably and delivers formatted HTML and plain-text emails straight to your support team.   ✨ Why Install Contact Form Processor?Smart 3-Tier Email Routing: Automatically routes form submissions to your configured Custom Support Email, falls back to Moodle’s global $CFG->supportemail, or delivers to the Primary System Administrator.   Built-In Visual Customizer (No Coding Required): Match your Moodle theme effortlessly from the admin settings panel. Customize your Primary Brand/Button Color, Card Background Color, Text & Label Color, Border Radius, Card Drop Shadow, and inject Custom CSS overrides.   Font Awesome 6 Icon Integration: Includes semantic Font Awesome 6 icons across form headers, labels, input fields, and buttons, with a built-in CDN toggle for Moodle themes that do not bundle Font Awesome 6.   Chromeless Iframe Embed & Live Generator (embed.php): Use the interactive Admin Embed Code Generator to preview and copy <iframe> snippets. Embed forms inside Moodle Pages, Labels, Course Summary Blocks, or external websites (WordPress, Shopify, static sites) with automatic postMessage height resizing.   5 Ready-to-Use Templates & FilterCodes Support: Works seamlessly with custom HTML forms, direct URL parameters (?type=support), or {form...} tags via the FilterCodes plugin:   contactus ({formcontactus}): Full Contact Us form (Name, Email, Subject, Message).   support ({formsupport}): Categorized Support Request form (Name, Email, Issue Category, Specific Subject, Related URL, Message).   courserequest ({formcourserequest}): Course Request form for learners to suggest or request access to courses (Name, Email, Course Name, Description).   quickquestion ({formquickquestion}): Streamlined in-course question form for authenticated users (automatically captures user's Moodle profile name, email, and course name).   checkin ({formcheckin}): One-click "I'm here!" attendance check-in button for logged-in students.
